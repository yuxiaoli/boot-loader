# Boot Loader

Pure static Vite + TypeScript, with no server, account, API, tracking or runtime CDN. No 3D runtime or image-generation assets. Native SVG is a compact Macintosh-inspired technical line drawing; its front plane uses a regular cabinet ratio and one consistent depth vector. Reference: the original Macintosh 128K at the Apple Museum in Prague (Wikimedia Commons). System fonts keep first load self-contained.

`src/destinations.ts` contains seven confirmed destinations and supplies static HTML, selector behavior, the virtual `/systems` directory and command routing. Source URL casing is intentionally preserved, including `winXP` and `daedalOS`. Visible counts are derived from that registry.

Vite's HTML transform writes complete content into three independent entry documents: `/boot-loader/`, `/boot-loader/visual/`, `/boot-loader/terminal/`. Ordinary live and source links work without JavaScript. Pages never needs an SPA rewrite. The home terminal is the final section. The visual route never loads xterm; home loads it on approach to the bottom, and terminal loads it when visible.

Visual direction: restrained Apple-inspired light gray and white, native system sans and mono, blue accents and technical line illustration. The default-light accent is `#0088FF`; filled buttons use the official increased-contrast light blue `#1E6EF4` with white text (4.57:1). Small blue text uses `#005EC4` to maintain contrast on the light-gray surface. Tokens are centralized in `visual-refinement.css`. Official color reference: https://developer.apple.com/design/human-interface-guidelines/color . Reduced motion disables transitions and cursor blinking.

The xterm.js console uses opaque `#11FF00` text on `#000000` with 1.25 line spacing. Its compact underline cursor uses native xterm blinking while focused, and remains steady on blur or when reduced motion is requested. The cursor-only theme is `rgba(17, 255, 0, 0.5)`; xterm 6 composites that alpha onto the black canvas as RGB(9,128,0), without changing terminal or text opacity. Commands are parsed locally against a whitelist, with a bounded virtual filesystem and Map of memory-only URL variables. No eval, subprocess, shell, host files, real environment or persistence is involved. Paste strips control codes and collapses newlines; Enter must be pressed separately. History is memory-only, capped at 100. Long command input has a horizontal viewport, so resizing does not truncate URLs. Focused Tab cycles matches from the typed prefix and Shift+Tab reverses them; matched keys cancel native focus navigation. Empty or unmatched Tab in either direction retains browser navigation. Edits, caret movement, history and Enter reset the cycle. The initial prompt displays `systems $` while `pwd` and `cwd` retain `/systems`; root displays `/ $`. `cls` is an exact `clear` alias. Canonical `open <URL|$name>` and `boot <system>` navigate the current tab by default; `--embed` explicitly uses the computer screen. `load` remains an exact `open` alias but is omitted from canonical command-name completion.

Home and terminal routes use a black HTML canvas behind the body; the visual-only route uses the light canvas. The light body and upper sections retain their light surface. Terminal focus/scroll tracks the visual viewport to select dark color-scheme and theme-color. The footer includes safe-area padding, and xterm's hidden textarea uses 16px input sizing to avoid iOS focus zoom. These are controllable page behaviors; browser keyboard/accessory chrome cannot be guaranteed without physical Safari testing.

Screen sessions are native accessible dialogs, with a readable, unwarped 3:2 display and explicit close/direct-open controls. Frames are created only after launch, replaced on switching and removed on exit/navigation. Known mixed-content or WebVM isolation limitations produce explicit direct-open options. Unknown timeouts and load events never claim success or cause automatic navigation. No target is proxied and no CSP/X-Frame-Options is bypassed.

Custom `open <URL|$name> --embed` requests (including the `load` alias) use an opaque-origin sandbox (`allow-scripts allow-forms`), no referrer, and explicit camera/microphone/location/payment/clipboard denials. They receive no top-navigation or popup permission. Registry demos additionally need `allow-same-origin` for their app storage; same-origin user-owned GitHub Pages demos are therefore trusted integrations, not a security isolation boundary. Their source links remain inspectable. WebVM cannot gain cross-origin isolation from this non-isolated Pages parent and uses a direct tab.

Use `develop` for implementation and GitHub Pages deployment. The Pages workflow validates both branches and deploys only `develop`; `main` is retained separately. The existing `github-pages` environment must permit `develop`. Do not bypass or change its protection rules as part of a release. `version.json` and the revision meta tag record the exact source commit. All action references are pinned.
